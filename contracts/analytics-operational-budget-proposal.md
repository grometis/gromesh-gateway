# Proposed Analytics operational budget — owner approval pending

This alternative B is authorized for isolated implementation and tests only. It does not replace the integrated Analytics v2 physical budget, enable serving under that budget, authorize merge, or activate endpoints. The four operations retain their OpenAPI, RBAC, cursor, attribution, provenance and error semantics. No operation is newly implemented by this contract-only PR.

`analytics-operational-budget-proposal.json` identifies the proposed internal profile and ceilings. Consumers must opt in explicitly on the server in an isolated composition; no query parameter, cursor, producer assertion or environment flag supplies proof. The old profile must remain unavailable when its physical requirement is unproven. `postgresPhysicalReadsProven` retains its original meaning and remains false.

One authorized analytics operation shares counters and remaining reservations across PostgreSQL, ClickHouse, history, fences, copy comparisons, pagination and serialization. Count database queries in the same unit; never add PG transport bytes to CH engine read bytes. PG elapsed wall time is conservative and includes transport. CH engine elapsed time and read statistics must be present and internally consistent. Missing accounting, overflow, partial data, cancellation or deadline refuse the operation rather than return a complete-looking result.

PG controls set statement_timeout at snapshot entry to at most the remaining execution allowance and any smaller existing session ceiling, transaction-local work_mem/hash limits, zero temporary-file allowance enforced by the reader role, disabled parallel gather/JIT, bounded results/transport/queries and existing admission slots. A role unable to enforce the protected spill ceiling must fail before the read. Nested history readers must not renew or increase a smaller statement ceiling. Request cancellation and stage reservations continue to bound later statements as time is consumed. work_mem is per operator; none of these proves PG table/index/TOAST reads or total backend memory. Index choice/plan estimates are not measured read cost.

CH applies the remaining rows/bytes/time and result allowance to each query with overflow=throw, plus per-query memory, threads and grouping controls. These are engine accounting/enforcement, not device I/O. Engine limits may detect overrun after internal work; they do not guarantee zero overshoot before refusal. The shared budget never accepts an over-budget result or silently grants a fresh allowance to the second query.

Materialization counts explicitly charged JSON bytes, not arbitrary JS heap or RSS. Serialization and synchronous stages check the monotonic deadline before and after work. Cancellation cannot promise hard real-time preemption of a stalled event loop. The operation wall ceiling includes its queue, active work and recovery. Existing nonce-bound backend termination has a separately bounded500ms attempt and destroys unusable transports; it must not renew the request deadline or permit a late result. Recovery connection control queries are distinguished from the active-query counter, never called measured physical work.

The boundary starts when the prepared controller creates its budget, after existing authentication/RBAC/Workspace guards and query parsing, and ends at operation cleanup before framework serialization and HTTP transmission. Those earlier security/session/token SQL queries and later framework/transport work are not accounted by this profile. It is not an eight-second guarantee for the entire HTTP request. If whole-HTTP accounting/deadline remains required, that activation gate is unmet; this proposal does not authorize a bypass or new global security architecture.

Each page reauthorizes current scope and obtains fresh evidence. Operational budgets do not prove copy completeness, conflict history, snapshot stability, Workspace ownership, revision served, or delivery from Kong. Those gates remain independent. `effectiveRevision` stays null. Responses add no public profile/evidence fields in this proposal.

Approval required: adopting this distinct profile instead of the integrated physical-read requirement, accepting its explicit exclusions and engine enforcement granularity, and future controlled migration of consumers. No default runtime factory or bootstrap is activated here.
