## Economic shutdown, reset and revocation

All three machines share `worker_state`, so the initial proposal runs only during qualification/CI sessions. A later hybrid can keep the coordinator running, but requires a reviewed module change; the default does not silently keep it billed.

`protected=true` and Terraform `prevent_destroy=true` intentionally block casual actions. For **own exact generation/IDs**, drain/offline the agents, prove queue empty, preserve required artifacts/checksums/manifest and authorize the lifecycle plan. Review three separate saved plans: (1) `server_protection_enabled=false` while still started, (2) `worker_state=stopped`, (3) restore protectiontrue while stopped. Confirm provider STOPPED, no queued work and continued disk/IP billing. No shutdown API is invoked by tests or `shutdownPlan()`. Wake requires a separately reviewed started plan (unprotect/start/reprotect if provider requires). Scaleway bills at least60minutes per resource/billing period; group short jobs to avoid repeated minimums.

Destroy/reset is a **separate explicit authorization**, not synonymous with stop. It requires exact owned IDs/tags/project/generation, drained agents, verified archived evidence+restore, a reviewed patch removing only the owned resources' prevent_destroy guards, exact saved deletion plan, and provider unprotection. This delivery provides no generic destroy script or automatic garbage collection. Never remove unrelated volumes, prune globally, or reuse untrusted disks as a trusted generation. Revoke node login/SSH key, remove the exact overlay peer, disable/delete only its node after offline, then revoke the matching dedicated credential. Rotate via new host/key generation and reauthenticate host key; never accept changed host keys automatically.
