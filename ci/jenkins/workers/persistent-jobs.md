# Persistência dos sete jobs — configuração sem execução

`persistent-jobs.mjs` gera um manifesto somente para main/prs/branches/discovery/status, images e references. Revisão SCM sempre40hex publicada, sem credencial de checkout público, polling ou triggers. Todos disabled=true. `persistent_job_extension.py` aceita somente o XML exato revisado e gera a extensão JobDSL; recusa troca de hash, revisão, RunAs, triggers ou seed base. O operador mantém a fonte `scripts/render_jobs.py` atualizada para carregar `config/j7/persistent-jobs.json` e adiciona a extensão somente depois de gerar o seed anterior sem modificações. Repetir a geração produz o mesmo resultado, sem substituir os jobs de ambientes existentes.

Aplicação inicial: só pelo Jenkins oficial HTTPS, primeiro snapshot com hashes de XML (sem exportar secretos), histórico,75plugins,0executores/agents/fila, ACLs/stores e global config; verificar targets ausentes e pais existentes. Validar lote completo antes de criar. Criar somente sete novos XML disabled; comparar todos os hashes/históricos antigos depois. Falha parcial não autoriza overwrite/delete/retry automático. Seed persistente é carregado pelo JCasC existente; não recarregar JCasC nem regenerar jobs DEV/HML/PRD para testar.

AuthorizeProject especifica os principais previstos `gromesh-ci-runner`, `gromesh-release-runner`, `gromesh-delivery-runner`; isso não os cria, não concede ACLs e não prova autenticação real. O Controller está com queueAuthenticators=[]: RunAs operacional requer configuração global e contas/grants revisados depois. O guard requireServiceIdentity bloqueia SYSTEM antes de alocar agents. Não habilitar estes jobs enquanto faltar esse gate, worker, configuração de runtime e credenciais qualificadas. Admin/SYSTEM lookup não é comprovação de binding positivo para publisher não admin. Writer permanece em gromesh-artifacts sem cópia/movimentação/grants novos.
