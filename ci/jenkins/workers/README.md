# Bootstrap de runtime/agente — inativo

Não executar no Mac mini, MacBook, Docker Desktop ou N2. Nenhum host está autorizado. Os perfis são contratos de recursos, não servidores provisionados. Coordenadores podem usar ARM64 após seleção explícita da arquitetura no perfil/autorização. Um host não recebe papéis de confiança diferentes sem reset de VM/disco/credenciais e rede comprovado. Um executor EXCLUSIVE por ambiente; CI de PR nunca recebe segredo de registry/App/storage durável.

O pacote verifica pré-requisitos e instala somente runtime e descritor em `/opt/gromesh/jenkins` e `/etc/gromesh-jenkins`. Não instala SO, pacotes, contas, serviço SSH/agent, Docker, firewall ou credenciais. Node26.13.0 e JDK21 precisam existir antes. CI/build requer pnpm10.28.0, Go1.27.3 e engine Linux rootless exclusivo. O operador prepara ferramentas oficiais verificadas nos caminhos fixos do checker. Requisitos: kernel>=5.15, cgroupv2 cpu/memory/pids, systemd e delegação efetiva; comprovar quotas/limits aplicados antes de ativar.

## Procedimento no futuro host autorizado

1. Selecionar revisão de pipeline revisada e publicada (40hex), arquitetura nativa, perfil, hostname e hash SHA256 dos bytes de `/etc/machine-id`. Não alterar perfis para baixar os guards. Congelar bundle de todos os arquivos runtime dessa revisão usando `buildRuntimeBundle(repo,sha)` de `worker-bootstrap.mjs`. O bundle é JSON com hashes, bytes e modos, sem segredos. Validar sua origem/revisão por canal administrativo independente: checksums do próprio bundle não autenticam um pacote recebido de PR. Não executar instalador proveniente de candidato não confiável.
2. Administrador do host instala checker revisado e Node em local root-owned não gravável pelo executor; cria `/etc/gromesh-jenkins` root0755. Preparar `authorization.json`, `profile.json` e `bundle.json` root0600, sem symlinks. Autorização: schema `gromesh-host-authorization/v1`, approved=true, id/role/hostname/machineIdHash/architecture/pipelineSha/executorUid exatos, issuedAt/expiresAt ISO UTC com validade máxima24h. A conta executor já deve existir com UID>=1000. Nenhum exemplo contém aprovação real.
3. Administrador independente verifica bloqueio de rota para N2, DNS/NTP/TLS, quotas, cgroups/delegação, ausência de workloads e mounts estranhos e reset efetivo. Registra `/etc/gromesh-jenkins/isolation-proof.json` root0600 com machineIdHash, bootId, observedAt(<1h), resetVerified/n2Denied/dns/ntp/egressTls/diskQuotaEnforced/delegated=true, privileged/foreignWorkloads=false e hostMounts=[]. É evidência administrativa, não autocertificação do executor. Checker mede CPU/RAM/disco/cgroups/engine/versões/fingerprintSSH no host; a evidência externa ainda deve ser auditada.
4. Como root executar `node worker-bootstrap.mjs check /etc/gromesh-jenkins/authorization.json /etc/gromesh-jenkins/profile.json`, depois `node worker-bootstrap.mjs install /etc/gromesh-jenkins/authorization.json /etc/gromesh-jenkins/profile.json /etc/gromesh-jenkins/bundle.json`. Falha retorna78 e nenhuma qualificação. Repetição de instalação idêntica não altera arquivos. Instalação parcial/divergente é preservada e recusada, para revisão humana; não há limpeza/upgrade destrutivo automático.
5. O descritor continua enabled=false/publicationEnabled=false/applyEnabled=false/artifactTransport.qualified=false. O retorno workerQualified=false é intencional mesmo com pré-requisitos satisfeitos. Mudanças nesses gates, credenciais SSH, registro de node e conexão exigem qualificação operacional posterior, sem reutilizar autorização expirada.

## Contrato de agente SSH (não instalado)

Nome e label = id do perfil; modo EXCLUSIVE; um executor; hostkey verificada contra fingerprint obtido por canal administrativo; nunca `NonVerifyingKeyVerificationStrategy`. Remoting/JAR deve ser obtido do Controller oficial e autenticado; JDK21 no host; diretório exclusivo por perfil e quota. Nenhum credentialId/hostname/node real é inventado. Configuração retornada por bootstrapPlan tem register=false e sshCredentialId=null: não é um node já registrado. Confirmar egress HTTPS ao Jenkins oficial, GitHub, Docker Hub e storage privado; sem exposição de porta inbound do agente, sem acesso à N2. Provar reconexão e isolamento/reset com um Run seguro somente após autorização de host.

`worker.json` serve CI/build. `github-app.json`, `images.json`, `publisher.json`, `references.json` servem coordenadores de runtimeConfig; precisam das propriedades específicas desses runtimes e credenciais de seus stores após revisão. Estes arquivos inativos não pretendem substituir qualificação de assinatura, ACL, ArtifactManager, budget ou publicação. Artefatos OCI continuam limitados20GiB; Kong pode exigir16vCPU/32GiB/200GiB, a medir sem reduzir o guard.
